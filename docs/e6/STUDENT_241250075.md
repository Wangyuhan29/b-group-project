## 5. 新版 E6 四项核心实现说明

对应 [小组新版报告](REPORT.md) 的四项代码阅读任务；实现位于 [autobuild.py](../../services/draft/draft/autobuild.py)，CLI 位于 [cli.py](../../services/draft/draft/cli.py)。以下说明对应本人实际运行源码 `b1643f47ba4e15af562768b76d97ad7d0608560f`，不是本人新增四项算法实现。

### 1. 固定 FROM 与必需指令

`instructions` 逐行折叠反斜杠续行并剔除注释与空行，行尾仍悬空续行时抛错；`prepare_candidate` 要求候选以带 sha256 摘要的 FROM 开头且全文件仅一个 FROM，初始镜像只接受同一标签的固定摘要，已有摘要不能替换，其余指令按 WORKDIR、COPY、RUN make、CMD 的原顺序匹配，只允许额外插入 RUN 修复，缺项或改写必填指令都拒绝。本人的截断续行与多阶段两个用例分别验证折叠解析的完整性校验和单阶段整体约束，不改变候选规则本身。

### 2. 首轮失败分类与停止条件

`classify_failure` 把 `/bin/sh: make: not found` 归为 MISSING_MAKE，网络与镜像源解析错误归为 INFRASTRUCTURE，其余构建错误归为 OTHER_BUILD_ERROR；`auto_build` 只在第一轮构建非零且分类为 MISSING_MAKE 时进入第二轮，首轮成功或其他分类（含基础设施错误）立即停止，第二轮构建失败也不再进入程序验证，避免把环境故障当作复现成功。本人 [result.json](../../artifacts/e5-e7/241250075-20261102/final-e6/evidence/result.json) 记录第一轮退出 1、MISSING_MAKE；[完整首轮 stderr](../../artifacts/e5-e7/241250075-20261102/final-e6/evidence/iter-01/build-stderr.log) 包含 make: not found。

### 3. 构建镜像与运行镜像一致

第二轮构建成功后立即执行 `docker image inspect` 取出镜像 Id 写入 attempts 记录，程序验证的 `docker run` 直接以该 sha256 Id 为镜像参数而不是复用可变标签，从数据上保证"验证的就是刚构建的那一个镜像"；运行附加 `--network none --cpus 1 --memory 128m --pids-limit 64`。本人第二轮 ID 为 `sha256:62dc13334e456a8d8e3b854d4413ce5952db29a4a255380173f69c55c5953267`；[image-inspect.json](../../artifacts/e5-e7/241250075-20261102/final-e6/evidence/iter-02/image-inspect.json)、result.json 的 attempts 与 verification.command 三处一致，运行参数包含 --network none。

### 4. 退出码和输出联合检查

验证结果同时保存退出码、actual_output、expected_output，比较前仅去除输出末尾换行；只有退出码为 0 且 output_matches=true 才置 SUCCEEDED，构建成功但输出不符仍判失败。本人第二轮 build_exit_code=0，最终 exit_code=0、actual_output 为 hello E3 加换行、output_matches=true；原始 [verify.log](../../artifacts/e5-e7/241250075-20261102/final-e6/evidence/verify.log) 与 result.json 对应。
