# ADR-241250075：本人学号课程容器与证据目录隔离

日期：2026-11-15。状态：已采用。

## 1. 背景

固定基线提供 E8/E9 B 轨道教学实现，参考运行使用宿主工具。手册要求优先使用课程容器；服务器为每名学生预置了独立的 `course1027-draft:<学号>` 容器。个人复跑不得修改原项目和他人的证据与容器。

## 2. 决策

- 基础镜像钉定本人学号容器 `course1027-draft@sha256:edcc9be4…`，仅补装 gcc/make/libc6-dev，保存 Dockerfile 与实际镜像 ID；不用他人的镜像摘要，避免把他人成果当作本人环境。
- 证据写到独立挂载目录（容器内 `/evidence`），仓库工作区只读参与实验；验证前后 `git status --porcelain` 均为 0 字节，"原项目不变"由空输出直接证明，而不依赖删除中间目录。
- 三种风格的补丁全部在各自独立副本应用、重扫并构建运行；macro 副本即任务要求的独立副本应用，direct/mixed 提升到同等强度。
- 新增三个测试分别覆盖宏定义缺失拒绝、补丁应用后的不动点、mixed 风格的最小修改面，不与组长和 241250017 的既有测试重复。

## 3. 备选方案与取舍

首版 Dockerfile 曾钉用 241250017 的基础镜像摘要（`a4561aac…`），构建前检查发现其属于他人学号容器，改为本人容器并重新实测（实测 SHA 相应更新）。宿主 GCC 直跑省去构建时间，但不满足容器优先要求。`--progress=plain` 在本机 docker 的传统构建器下不可用，按现有可用旗标执行（与既有归档一致），构建日志完整保留。

## 4. 结果与限制

12 项测试与 E8/E9 验证全部通过；三份原项目指纹不变；manifest 覆盖全部 111 个入库证据文件，三个应用副本的 `app`/`main.o`/`helper.o` 编译产物不入库，保留构建与运行日志。结果不扩展为任意复杂 Makefile 的通用结论；E10 未包含在本次范围。服务器执行输出保留在 `/root/241250075/run.log`，归档只含证据文件本身。
